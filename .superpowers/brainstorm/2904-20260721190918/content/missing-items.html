OCR 漏品項 — 解決方案

Gemini 在單頁內偶發性漏辨識 1-2 個品項（非整頁截斷）

根因分析

目前 prompt 已說「保持項目在圖片中出現的物理順序」和「忽略表頭、頁尾」，但沒有明確要求「不要遺漏任何品項、完整輸出所有行」。 Gemini 可能因為以下原因跳過品項：

  • 該品項的品名模糊、條碼不清 → Gemini 認為「辨識不出來乾脆不輸出」
  • 靠近頁尾/頁首邊界 → 被誤判為表頭表尾而忽略
  • 輸出 token 接近上限 → 最後 1-2 項被截斷（即使單頁也可能觸及 8K 限制）
  • 品名過長或不常見 → Gemini 跳過「不確定」的項目

方案：雙層防禦

第一層：Prompt 強化

在 prompt 加入以下約束：

  1. 完整性要求：「請逐行輸出每一筆藥品項目，不可跳過任何一行。即使某欄位無法辨識（條碼模糊、品名不清），仍需輸出該行，將無法辨識的欄位設為空字串。」
  2. 總數自檢：「輸出完成後，請在 JSON 中加入 item_count 欄位記錄實際輸出的項目數。」
  3. 邊界提示：「頁尾的頁碼行 不是藥品，不要輸出；但頁尾前一行的藥品不可遺漏。」
第二層：後端驗證 + 自動重試

在 parseBatchWithGemini 回傳後加入驗證邏輯：

  1. 項目數檢查：若 items.length < 40（正常一頁 44 項，容忍 ±4），標記為「可能漏項」
  2. 自動重試：漏項時自動重試一次（已存在重試機制，只需調整觸發條件）
  3. 警告標記：重試後仍不足時，回傳中附加 warning 欄位，供前端顯示
第三層：前端使用者提示（輕量）

在 ImportOverlay 或 PreviewPanel 顯示摘要資訊：

📋
OCR 辨識完成
總頁數 6 頁，辨識 262 項 （預期 ~264 項，可能有 2 項遺漏）
頁 3：42 項 | 頁 5：43 項 ← 需人工確認

邊界測試

# 場景 期望行為
1 正常頁 44 項全辨識 items.length=44，無警告
2 末頁只有 30 項（正常） 不觸發漏項警告（末頁特殊處理）
3 某頁 42 項（漏 2 項） 自動重試 → 仍 42 → 標記 warning
4 某頁 39 項（漏 5 項） 自動重試 → 仍 39 → 標記 warning
5 重試後補回 44 項 清除 warning，正常匯入
6 全部頁都正常 前端顯示「辨識 N 項」，無警告
7 item_count 與實際 items.length 不符 以實際 items.length 為準，記錄 log 不一致
A

三層全上 (Recommended)

Prompt 強化 + 後端驗證重試 + 前端警告提示。最完整的防禦。

B

只做 Prompt + 驗證

不做前端提示，只靠後端自動重試。較簡單但使用者不知情。

C

只做 Prompt 強化

最輕量。只靠 prompt 約束 Gemini，不做任何驗證。
